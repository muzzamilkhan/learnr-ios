# LearnR iOS

The native child client, and the Swift port of the question engine. Children
only — a parent uses the web app, and the only way in is the four-character code
a parent hands over.

## Cross-repo changes: raise an issue, never a commit

**Anything that needs to change in `muzzamilkhan/learnr` gets a GitHub issue
raised against that repo. Do not edit, commit to, or push to `learnr` from this
repo's work.**

That covers the API (`apps/api`), the shared engine (`packages/core`), the web
app, the contract, and the docs under `apps/api/docs` — the handoff included.

Why: `learnr` is live on Vercel and Fly, and the API is being worked on from
another machine. A commit landing there from an iOS session is a change nobody
on that side asked for, reviewed, or expected. An issue reaches them; a push
surprises them.

```bash
gh issue create --repo muzzamilkhan/learnr --title "..." --body-file ...
```

Say what this client needs and why, name the exact files or endpoints, and note
what iOS is doing in the meantime. Link the issue number from any local comment
or README line that depends on it.

Existing examples: `learnr#4` (untyped API responses), `learnr-ios#1` (stale
server references, raised the other way).

## The engine is a port, not a rewrite

The TypeScript engine in `learnr/src/lib` is the oracle. This port is verified
against vectors generated by running that source — never by reimplementing it in
the generator, which would only prove the copy agrees with itself.

When adding a ported module: generate its vectors from the real TypeScript
first, then write the Swift against them. Regenerate vectors only in a commit
that does nothing else and says why.

Four traps already found, each a place where idiomatic Swift silently diverges:

- `round(-2.5)` is `-2`, not `-3` — JS breaks ties toward +∞
- `String(2.0)` is `"2"`, not `"2.0"` — this text reaches a child in a prompt
- `-2 ^ 2` is `-4` — unary binds at 6.5, between `*` and `^`
- `1 && 2` is `true`, not `2` — the operators return Bool, unlike JS's own

## Building

```bash
xcodegen                      # regenerate LearnrApp.xcodeproj from project.yml
cd LearnrEngine && swift test # engine tests
```

`project.yml` is committed; the `.xcodeproj` is generated and gitignored. Change
build settings there, not in Xcode's UI, or the change is lost on regeneration.

## Conventions

- Best-effort on the play path: a failed sync costs history, never the question
  in front of the child.
- Every attempt carries a client-chosen id; the server dedupes on it. A retried
  flush must not double-count.
- Each sitting gets its own session id. Sharing one across sittings lets the
  server re-chunk a paid round and quietly cost a child their stars.
